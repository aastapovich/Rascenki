# Вклад в проект / Правила разработки

Главное правило контроля изменений:

- Любые исправления или дополнения должны улучшать код, оптимизировать реализацию и соответствовать правилам PEP (в первую очередь PEP 8 для стиля и PEP 257 для докстрингов).

Рекомендуемые практики и инструменты:

- Форматирование: используйте `black` для автоматического форматирования кода.
- Статическая проверка стиля: используйте `flake8` (или `ruff`) для обнаружения проблем со стилем и потенциальных ошибок.
- Сортировка импортов: используйте `isort`.
- Тесты: добавляйте/обновляйте unit-тесты (pytest) при изменении логики; все изменения должны проходить тесты.
- Типизация: по возможности добавляйте аннотации типов и поддерживайте совместимость с указанной версией Python в `pyproject.toml`.

PR / Commit message guidance:

- Пишите осмысленные сообщения коммитов и описания PR на русскомязыке.
- В описании PR указывайте: цель изменения, что улучшено/оптимизировано, какие тесты добавлены/обновлены.

Минимальный чек-лист перед слиянием:

1. Все unit-тесты проходят (`pytest`).
2. Код отформатирован (`black`) и проходит `flake8`/`ruff` без критичных нарушений.
3. Докстринги и типы обновлены, если логика изменилась.
4. Никаких временных отладочных `print` или закомментированных больших фрагментов кода.

Спасибо за вклад!
